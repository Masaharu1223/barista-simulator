## コンセプト

複数の注文を見て、エスプレッソの抽出回数を最小にする段取りを組むパズル。
マシンは1回にシングルかダブルのどちらかしか抽出できず、実時間で25〜30秒かかる。
ダブルは1ショット×2個が出るので、どの注文にどう振り分けるかが核。

## レシピ表

| ドリンク | M | L |
|---|---|---|
| カフェラテ | 1 shot | 2 shot |
| バニララテ | 1 shot | 2 shot |
| アメリカーノ | 2 shot | 3 shot |

HOT / ICE は見た目のみに影響し、必要ショット数は変えない。

## v1 のルール

1. 抽出時間はシングル 25秒 / ダブル 30秒の固定値
2. マシンは1回1抽出（brewing 中はボタン無効）
3. マシントレイにショットが残っている間は次の抽出を開始できない
4. 余ったショットはドリップトレイへのドラッグで廃棄（廃棄カウンタが増える）
5. 満杯のカップへのドロップは拒否し、ショットは手元に戻る
6. カップは注文ごとに自動生成
7. 注文キューは最大4件。1件提供すると次が入る
8. 提供はボタン（将来のD&D差し替えのため単一関数に隔離）
9. スコアは抽出回数と廃棄ショット数
10. ショットの鮮度/劣化は v1 では実装しない

## レビュー

### 実装の要点

- **ダブルの分割を操作として作らなかった。** 抽出完了時に single なら Shot 1個、
  double なら 2個を生成する。実機のダブルスパウトと同じモデルで、これによって
  「注文を見て抽出回数を最小化する」というパズル性がデータ構造から自然に出る。
- **カメラはバー視点を基準にした。** マシン・作業台・提供台を同一画角に収める配置に
  したので、ショットのドラッグがカメラのカットをまたがない。Q/E のスナップズームは
  その上に乗せている。
- **ドラッグ位置はストアに載せていない。** 毎フレーム更新される値なので、
  `src/scene/dragState.ts` のモジュール変数で共有している。
- **ショットは自分の置き場所（slot）を持つ。** 配列の並び順で位置を決めると、
  1つ取り出したときに残りのショットが勝手に移動してしまうため。

### 計画から変えた点

- `Shot` に `slot` を追加（上記の理由）
- URL の `?seed=` で注文列を固定できるようにした。動作確認の再現性のため
- 見た目の確認用に `scripts/screenshot.mjs` を追加。WebGL の描画は型チェックでも
  ユニットテストでも検証できないため

### 検証結果

`npm test` 21件パス。実画面での通しシナリオも全項目確認済み。

| 項目 | 結果 |
|---|---|
| 注文が4件並び、カップが出る | OK |
| 抽出中は次の抽出を始められない | OK |
| ダブル抽出でショットが2個出る | OK |
| トレイに残っている間は次の抽出ができない | OK |
| ドラッグでカップに注げる | OK |
| 満杯のカップに落としても増えず、ショットはトレイに残る | OK（赤いリングで表示） |
| 何もない場所に落としてもショットは失われない | OK（自分のスロットに戻る） |
| ショットを捨てると廃棄カウンタが増える | OK |
| 提供すると提供台へ移動し、次の注文が入る | OK |

seed=7 でダブル1回から2杯（#1・#3）を完成させ、抽出1回・廃棄0で提供まで到達することを
実画面で確認した。狙っていた「無駄のない段取り」が成立している。
