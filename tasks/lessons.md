# 開発時の教訓

## 抽出中止機能: 「捨てる」という言葉から中身の量を推測しない (2026-08-14)

**何をしたか**: 「抽出中にボタンを再度押すと中止でき、出てきたショットはゴミ箱に捨てる」という
依頼を、「中止＝満タンのショットが即座に出てくる（早送りで完了）」と実装した。

**何が問題だったか**: このゲームの核心ルールは「抽出には実時間で25〜30秒かかる」こと。
「中止＝満タン完了」にすると、ボタンを押してすぐ中止するだけで待たずに満タンのショットを
得られてしまい、核心ルールを回避できる「ズル」になっていた。ユーザーはプレイして初めて
これに気づき、修正を依頼した。

**教訓**: ゲームの核心的な制約（今回は「実時間で待つこと」）に触れる可能性がある新機能を
実装するときは、曖昧な表現（「捨てる」など）から都合よく量やタイミングを推測せず、
まず「プレイヤー有利に倒れていないか」を自問する。迷ったら、より厳しい（プレイヤーが得を
しない）解釈をデフォルトにするか、実装前にユーザーに一言確認する。

**次から気をつけること**:
- 新機能が既存の「時間コスト」「ショット数」などのスコア系ルールとどう相互作用するかを
  実装前に自分で表にして確認する
- 「捨てる」「片付ける」などの操作系の言葉だけでなく、「なぜその操作が必要になるのか」
  （＝どんな不正/ズルを防ぎたいのか）を先に言語化してから実装する
